# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

- Короткую инструкцию запуска и прогона теста. В описании PR ответьте, где проверяется результат AI, что происходит при сбое, какой AI вы использовали и что проверили самостоятельно. Если работали без AI, укажите это.

После сдачи бот может задать один-два коротких вопроса по вашему коду. Используйте учебные данные. Если не уложились по времени, отметьте незавершённые части в PR.

## Решение

### Запуск и тесты

```sh
node server.mjs   # или npm start; страница: http://127.0.0.1:3000
npm test          # или node --test
```

Нужен Node.js 20+, зависимостей нет. Тесты (`test/triage.test.mjs`, встроенный `node:test`) поднимают сервер на свободном порту и проверяют: успешный разбор, все сценарии сбоя модели (`[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`), укладывание в лимит 300 мс, а также все варианты невалидного ввода и битый JSON.

### Что сделано

- **Валидация ввода.** Битый JSON, отсутствующий, нестроковый или пустой (в том числе из одних пробелов) `text` возвращают `400 {"status":"invalid_input"}`. Тело запроса ограничено 64 КБ.
- **Проверка результата AI** — функция `parseModelOutput` в `server.mjs`. Ответ модели принимается, только если это JSON-объект, `topic` входит в `delivery | pricing | other`, а `draft` — непустая строка. Всё остальное считается сбоем.
- **Сбои и таймаут** — функция `triage`. Модель ждём не дольше 300 мс: по таймауту запрос отменяется через `AbortSignal`, а `Promise.race` гарантирует ответ, даже если провайдер сигнал игнорирует. Таймаут, исключение и неподходящий ответ дают `200 {"status":"manual_review","topic":null,"draft":null}`. Имитатор модели не менялся.
- **Страница.** При успехе показывает тему и черновик. При `manual_review` выводит понятное сообщение менеджеру. Предыдущий черновик очищается сразу при отправке новой заявки, поэтому после сбоя на экране не остаётся устаревшего ответа. Ответы на устаревшие запросы игнорируются, кнопка блокируется на время запроса, результат выводится через `textContent` (без XSS).

### Польза для менеджера

Менеджер не получает ни пустой, ни мусорный черновик: при любом сбое AI он сразу видит, что заявку нужно разобрать вручную, и ни одна заявка не теряется. Пользу можно измерить средним временем от поступления заявки до ответа клиенту и долей черновиков, отправленных без правок.
